# 灰烬谷：玩法优先的开放世界路线

用户已确认按下列顺序推进。每阶段先交付可试玩版本，再按验收推进；本文件是后续协作的顺序依据。目标循环：**探索找目标 → 战斗取材料和装备 → 回城成长与搭配 → 挑战更危险区域 → 获得新的探索目标**。

| 阶段 | 内容 | 当前状态 | 验收重点 |
| --- | --- | --- | --- |
| 1 | 正式冒险开局、三槽存档、装备实例 | 本次实现 | 刷新/重开浏览器续玩，背包与世界变化保留，冷却和持续技能不中断、不重复领奖 |
| 2 | 三片区域、危险等级、探索迷雾、兴趣点、传送 | 待开发 | 每区约 6–8 个值得探索的地点；能自由选择去向，高危区有明确提示，已探索内容可记住 |
| 3 | 资源掉落、制作、强化、分解与铁匠 | 待开发 | 约六类新增资源、有目的的掉落来源，强化 +0 至 +5，旧装备可回收，材料形成消耗循环 |
| 4 | 敌人差异、精英和区域首领 | 待开发 | 约 8–10 种普通敌人、三类精英机制；烬甲处刑者、菌冠祭司、渎圣主教各有前摇和阶段变化 |
| 5 | 装备词缀、属性分工和比较 | 待开发 | 主手、头/胸/腿/靴、双戒指、项链；逐件装备属性、清晰比较、有限重铸 |
| 6 | 技能符文、套装与构筑 | 待开发 | 先做炎剑、魔镰、雷杖；每个技能两种变化，套装能改变打法；弯刃仍无主动技能 |
| 7 | NPC、阵营、委托和世界事件 | 待开发 | 探索、材料、战斗有连续目标，奖励只结算一次；事件有预告、有选择、有结果 |
| 8 | 可选终局难度、数值平衡和体验优化 | 待开发 | 能反复挑战，完善掉落/成长节奏、移动端和特效性能 |

## 第一阶段交付

- 「冒险存档 / 新建角色」提供三个角色槽，名称可修改；「继续冒险」进入最近的有效存档。
- 冒险从长剑、余烬法杖、皮甲、两种药水各三瓶、古木四份和月露草两份开始。全武器试用、祭坛试用独立保留，不写入冒险槽。
- 每 20 秒游戏时间、物品/任务进度变化后、打开背包/暂停和页面隐藏时保存；可手动保存、导出/导入 JSON。
- 记录种子、位置与成长、36 格背包、合成格、手中物品、四件穿戴、任务与职业解锁、世界实体/掉落/碰撞、随机状态、刷怪计时和持续法术。
- 逐件装备有稳定身份，移格/穿戴/丢弃/拾回均保留。强化、词缀、符文字段目前为空配置，实际玩法在后续阶段实现。
- 探索、已开宝箱、净化节点、首领标记已预留存档字段；本阶段没有据此虚构新区域、宝箱或首领内容。
- 每槽保留上次不同的有效版本。主记录损坏时读取备份；不兼容版本、非法物品、重复装备身份等导入会被拒绝。死亡不会覆盖最后一份活着的存档。

存档目前在浏览器本地，没有账号云同步。稳定试玩域名继续沿用；不同域名、不同设备、离线文件之间用 JSON 迁移。后续改动存档结构时必须显式迁移或提高格式版本，不能悄悄重置玩家进度。

## 第二阶段的实施顺序

1. 将区域边界、危险级别、资源和敌群放入共享内容表，让地图、提示和模拟查询共用定义。
2. 接入基于角色实际行走的探索网格与地图迷雾，保存已探索区域。
3. 先把初始区域做成一段完整探索路线：路标、营地、战斗点、奖励点与回程路线。
4. 再扩展腐化林地和圣域遗迹，主要道路保证连通，种子变化用于支路和兴趣点。
5. 接入可发现、可记录的传送点，把探索奖励与回城整理连接起来。
6. 验证三片区域的可达性、危险提示、奖励首次结算、刷新续玩和手机运行，然后进入资源制作阶段。

后续数值以实际战斗和掉落测试调整。保持像素画风、四方向穿戴挂点、武器对应三技能和移动端小圆键布局。
